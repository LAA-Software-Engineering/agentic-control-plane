## [Unreleased]

### Added

- **`.agent` CLI ingestion, `agentctl export`, YAML demotion, and docs re-lead** (issue #200): `.agent` becomes the authoring surface and YAML becomes compilation output / interchange (ADR 003). `project.LoadProject` now discovers every `.agent` file under the project root (skipping dot-directories like `.agentic`) and compiles the whole set through the checker (`internal/lang/check`) — type and effect checking plus the positional workflow-argument rebind — merging the **checked** resource projection (not the bare lowering over-approximation) into the graph that `validate`/`plan`/`apply`/`run`/`export` consume; diagnostics surface as load errors with `file:line:col` positions. To make the loader depend on the checker, `MergeLowered` moved from `internal/project` to `internal/lang/lower` so `check` no longer imports `project` (the former cycle). **Control-flow workflows are refused at load**: the resource graph cannot represent `if`/`for` (it flattens both arms for effect analysis) and the execution IR that can (`internal/execir`) is not wired into the engine, so a workflow using a conditional or loop is a compile error naming the construct — only straight-line steps and `parallel { }` static fan-out reach the run path, until `execir` executes on the engine (a #207 follow-up). New **`agentctl export --format yaml`** materializes the compiled graph as a deterministic multi-document YAML stream to stdout (nothing written to disk by default, ADR 003 decision 1) or, with `--output DIR`, as a loadable project (`project.yaml` plus one file per resource under `resources/`, since the loader rejects multi-document files) that round-trips back through the loader to an identical graph (positions and the rewritten import list are not identity). **`agentctl fmt`** now formats `.agent` sources to canonical form via a promoted, production AST printer (`lang.Print`/`lang.Format`, extended for the #199 surface with precedence-aware minimal parenthesization and idempotent parse→print→parse→print); the YAML formatter is retained but not extended, and comments are not preserved on either surface. **`agentctl init`** scaffolds a `.agent`-led project (`main.agent` holds the workflow; tools/policies/`project.yaml` stay YAML) that `init`→`validate` still passes. A new `examples/agent-quickstart` demonstrates the surface (an agent plus a conditional workflow); every existing example remains YAML, proving the ingress. README, `docs/DESIGN_DOC.md` §7 and §10, and `docs/LANGUAGE.md` re-led on `.agent`. The YAML diagnostic helpers (`internal/spec/yamlhint.go`, `internal/project/yamlpaths.go`) are unchanged, not extended.

- **`.agent` conditionals, loops, dynamic fan-out, and the execution IR** (issue #199): the `.agent` frontend gains control flow — `if`/`else`/`else if`, `for x in <collection>`, and `parallel for x in <collection>` (dynamic fan-out) — plus the boolean expression language they require (`==` `!=` `<` `<=` `>` `>=` `&&` `||` `!`, string/number/`true`/`false` literals; no arithmetic; comparisons do not chain). Per ADR 002 §4 no control-flow field lands on `WorkflowStep`: control flow lowers to a new **execution IR**, [`internal/execir`](internal/execir) (`InvokeTool`/`InvokeAgent`/`InvokeWorkflow`/`Let`/`Fork`/`Branch`/`Loop`/`Return`), the second of ADR 002 §5's two sibling projections. [`lower.LowerExec`](internal/lang/lower/exec.go) produces it by reading the AST directly (never the resource projection, which cannot represent control flow), and `check.Check` exposes one `execir.Program` per workflow on `Program.Executables`. A self-contained [`execir.Interp`](internal/execir/interp.go) executes a program against an injected `Invoker`, running a `parallel for` (and `parallel {}` `Fork`) with **bounded concurrency** and isolated per-iteration scopes. **One scope model, shared by the type checker and the interpreter and enforced as a compile error**: an `if` is exclusive choice with a definite-assignment join (each arm checked against the pre-`if` scope; a name is in scope afterward only if bound in both arms; differing arm types join to a union → untyped); a sequential `for` may run zero times, so the loop variable and body-local bindings are not in scope after the loop while a pre-existing name survives, and a `return` inside a sequential loop returns from the workflow and halts it; parallel control flow (`parallel {}`, `parallel for`) isolates each branch/iteration and rejects `return`. The type checker is the **name-resolution authority**: a reference to a name the scope model says is absent (a one-arm `if` binding used after the `if`, a loop variable used after the loop, any never-bound name) is a compile error (`unresolved reference`) from the same env, so a program cannot type-check under one model and fail under another; `==`/`!=` are total and panic-free over the JSON objects and arrays a workflow input holds (structural, numeric-aware equality). Positional `workflow:` arguments are rebound to real parameter names on the execution IR too, not only the resource projection (`applyExecRebinds`). **Effect soundness is the union over all branches by construction**: `lower.LowerFile` flattens every conditional arm and loop body into resource steps, so the existing, unmodified `effects.Compute` walk yields the union — a branch reaching an operation the `effects { }` clause does not declare fails compilation exactly as a straight-line reach would (proven by `TestCheckControlFlow_EffectSoundnessUnionOverBranches`). **Conditions are pure**: a call inside an `if` (or a comparison operand) is a diagnostic — bind it to a name first — which keeps conditions effect-free and sidesteps short-circuit-vs-effect questions. **Termination is bounded**: the surface has no `while`, and the interpreter caps the iteration count at the new `limits.maxLoopIterations` (`spec.DefaultMaxLoopIterations` = 1000, overridable per project/workflow). **Follow-ups, not shipped here** (all land with `.agent` ingest into the CLI/engine): the plan-hash fold exists as a mechanism (`plan.WorkflowSpecHashWithExec` mixes `execir.Program.Digest` into the spec-hash, unit-tested) but no production `plan`/`run` path constructs an `execir.Program` yet, so `WorkflowSpecHash` still hashes the resource envelope only; the YAML ingress path still executes as a `WorkflowStep` DAG rather than converging on the execution IR (ADR 002 §5's dual-ingress convergence is a design target here, not yet shipped); and `apply` persisting the compiled program / `run --resume` pinning it await the content-addressed deployment snapshot of #207. `execir` executes as a library today. `docs/LANGUAGE.md` "Control flow and the execution IR" section; DESIGN_DOC §7.4.

- **`.agent` type and effect checking** (issue #198): new [`internal/lang/check`](internal/lang/check) implements the ADR 002 §5 "checked program" between the #196 typed AST and the two sibling projections. `check.Check(f, check.Options{...})` computes the workflow's actual effect bound by lowering **every file in the compilation unit** (`f` plus `Options.Files`) through the existing `lower.LowerFile` (#197), merging them into one graph, and calling the existing, unmodified `effects.Compute` (#189) — never a second effect walker — so the `.agent` and YAML ingress paths agree on a bound by construction (`TestDifferential_AgentAndYAMLProduceIdenticalEffectBounds` proves this for a paired fixture; regression tests pin the cross-file case where a callee's own body must be lowered, not merely classified). The declared `effects { }` clause becomes **checked**: a computed effect the clause doesn't cover is an error with a witness path (reusing #190's rendering, now exported as `effects.FormatWitness`, `AUTONOMOUS` tag included on agent-selection edges); a declared effect the body can't reach is a **warning**, which needed a new `Severity` on `lang.Diagnostic` (`SeverityError` zero value — every pre-existing diagnostic is unaffected — or `SeverityWarning`; `Diagnostics.HasErrors()` tells them apart, and `Diagnostics.AsError()` gives a safe `error` conversion — a bare interface conversion or `len(diags)!=0` does not, since a warning-only slice is still non-empty). Also type-checks agent invocation arguments, workflow invocation arguments (matched to declared, ordered parameters, including call-site arity — an unknown named argument, an extra positional argument, and a parameter left unbound are all errors; a positional argument fills the next slot not already claimed by a named one, so mixed calls bind correctly), value flow between bindings, and `return`, reusing `schema.Document`/`TypeSet.Compatible` (#193) — a `TypeRef` name resolves to `<dir>/schemas/<Name>.json` (a new naming convention this issue introduces; a missing schema file checks as untyped/gradual, but one that exists and fails to compile is a reported error, not swallowed). `Check` also **rewrites** the lowered `workflow:` step `with:` keys it publishes on `Program.Graph` from lowering's placeholder `arg0`/`arg1` form to the callee's real, resolved parameter names (position-correlated against `WorkflowStep.WorkflowPos`, not a re-derivation of lowering's step-id scheme; each matching step's `with:` map is rebuilt fresh from its original entries in one pass rather than mutated key-by-key, since lowering's placeholder namespace and a callee's real parameter namespace share one map — a parameter legally named `arg1` would otherwise alias one rename's target onto another rename's source) — a positional workflow call that type-checks clean now also produces an executable graph. **Type-checking, rebinding, and effects-clause-checking all run over the WHOLE compilation unit** (`f` plus every `Options.Files` entry, the same set lowered and merged onto `Program.Graph`), not just `f` — a positional call or an `effects{}` clause living in a `Files`-only file is checked and rebound identically to one in `f`. An `agent:` call has no such parameter list to rewrite against (an agent's `input` is one type, not named fields): every call shape but a single positional argument is diagnosed — zero arguments against a known input type is an error, a single named argument or more than one argument is a warning naming the call unverified, never a silent pass. Scope: agents/workflows declared in the same compilation unit only; `.agent` ingress into `agentctl`/`project.LoadProject` is not wired up (follow-up). `docs/LANGUAGE.md` "Type and effect checking" section.

- **`.agent` AST → resource-model lowering with source maps** (issue #197): new [`internal/lang/lower`](internal/lang/lower) lowers the #196 typed AST into the existing resource model — the **resource projection** of ADR 002 §5 (`lower.LowerFile(f, lower.Options{}) (*lower.Result, lang.Diagnostics)`), a sibling of the future execution lowering (#199), never its input. `grants` become `AgentSpec.Tools` (an autonomous capability bound); a dotted callee lowers to a `uses:` tool step, a single identifier to a `workflow:` step when it names a workflow declared in the same file (or `Options.Workflows` for other files) and an `agent:` step otherwise, with duplicate and cross-kind names reported as diagnostics; named args become `with:` keys and positional args placeholder `arg0…` keys; workflow param fields lower to `${input.…}` and bindings to `${steps.<id>.output.…}` (a bare whole-input reference is a diagnostic — the interpolation language has no token for the entire input); `return` lowers to `output.value`; nested calls SSA-flatten into `<parent>_arg<i>` temp steps; and sequential/`parallel` statements lower to the #192 `needs` graph (fan-in). **Generated step ids are structural — enclosing workflow, binding name, AST child path — never source-derived (ADR 003), so reformatting or unrelated inserts produce a byte-identical graph and no spurious `plan` diff.** Positions are stamped on the IR nodes (#187) and in an auxiliary `lower.SourceMap` keyed by structural identity, so a validation/policy/effect diagnostic on lowered IR underlines the `.agent` call site. [`project.MergeLowered`](internal/project/graph.go) folds a result into a `ProjectGraph`. **Known Epic F gap (#188/#204):** grants bind multiple operations per tool, but `AgentSpec.Tools` as consumed by the #160 agent loop advertises one operation per tool, so the ADR 002 fixture is valid on everything lowering owns (steps, `needs`, references) but does not yet pass full agent-spec validation; lowering preserves every grant. Lowering section: [`docs/LANGUAGE.md`](docs/LANGUAGE.md); plan: [`docs/plans/197-lowering.md`](docs/plans/197-lowering.md).

- **`.agent` lexer, parser, and typed AST** (issue #196): new [`internal/lang`](internal/lang) parses the ADR 002 surface syntax into a typed AST via `lang.Parse(file, src) (*lang.File, lang.Diagnostics)`. Scope is **parsing only** — no lowering (#197), no type/effect checking (#198), no conditionals/loops (#199). Every token and AST node carries a position that is the *same type* as the IR positions from #187 (`lang.Pos = spec.Pos`), so lowering can copy positions with no conversion. The parser recovers after each error (declaration/statement/list/line synchronization) so malformed input yields **multiple** positioned diagnostics in one pass rather than stopping at the first. Grants (`tool.<name>.<operation>`) and effects (bare dotted identifiers) are kept in distinct namespaces per the ADR 002 amendment (#188): a grant written as a bare name, or an effect written with a `tool.` prefix, is a diagnostic. Deliberately omits anonymous functions and any call-site `approve` statement (ADR 002). Grammar reference: [`docs/LANGUAGE.md`](docs/LANGUAGE.md).

- **Workflow-level human approval steps** (issue #195): `WorkflowStep.approval` is a graph node (ADR 002) that suspends the run for a human decision that is not a tool call. `approval: true` or `{ description, redactKeys }` — XOR with `uses` / `agent` / `workflow`. Unknown keys under `approval:` fail load (`KnownFields`) with typo suggestions. Reuses the #106 HITL checkpoint and `--decision approve|reject|edit` resume path (`switch` is not applicable). Step output is the reviewed `with:` payload. **Reject aborts the whole workflow** (same as tool-call HITL); an approval step in a parallel group **suspends only its branch** and resume reconstructs the #192 completion set. Audit chain verifies across suspend/resume. DESIGN_DOC §7.4 / §13.2.

- **Subworkflow steps** (issue #194): `WorkflowStep.workflow` names another `Workflow` in the project graph (ADR 002 — static callee, no conditionals/loops). `with:` maps to the callee's input; the callee's `output.value` is the step output. Validate rejects direct/mutual recursion, dangling callees, and step ids containing `/` (qualified `run_steps` ids must be injective) with YAML positions, and caps nesting at `spec.limits.maxWorkflowNesting` (default 8). **Policy (fail-closed):** both the caller's and the callee's `spec.policy` must pass (`policy.StricterOf`); tighter cost/time ceilings win; HITL `interruptOn` keys and `redactKeys` are unioned; allowed decisions and edit allowances are intersected (`PolicySpec()` does not alias or last-write-win callee HITL). Effect bounds walk `workflow:` steps (caller bound includes callee effects; witness path shows nesting). Traces emit `workflow_call_started` / `workflow_call_finished` (taxonomy 3) with `callStack`. Checkpoints stack mid-subworkflow progress (each nested frame validated against the named callee using the resolved nesting cap). Nested DAGs share the parent's live cost total. Sequential YAML without `workflow:` is unchanged. DESIGN_DOC §7.4 / §13.2.

- **Typed step outputs and schema wiring** (issue #193): `input.schema` / `output.schema` files are compiled onto the project graph (not only checked for existence). Validate statically checks `${steps.<id>.output…}` interpolations against a producing agent's declared output schema and a consuming agent's declared input schema, and reports mismatches with YAML positions. Absent schemas stay allowed (gradual typing). DESIGN_DOC §13.1 / §13.3.

- **Parallel workflow branches and fan-in** (issue #192): `WorkflowStep.needs` is a static list of step IDs (ADR 002 graph structure — no `when` / `foreach` / expressions). Workflows with no `needs:` keep implicit sequential YAML order. When any step declares `needs:`, omitted `needs` means a root; independent roots run concurrently (bounded worker pool, default 8) and a join lists every branch so `${steps.*}` sees all upstream outputs. Validate rejects cycles and dangling `needs` with YAML positions. Checkpoints store a per-step `completed` set so resume continues a partially finished parallel group without replaying done branches — including a sibling that finished successfully while another branch was saving an interrupt snapshot. Concurrent steps admit and commit cost under the run lock against live `totalCostUsd` so two in-flight branches cannot jointly exceed `execution.maxTotalCostUsd`. Trace events add `logicalOrder` (YAML index) in `data_json` for deterministic replay; `audit verify` still covers the insert-order chain. Workflow spec hashes include `needs` and ignore diagnostic `NeedsPos`. DESIGN_DOC §7.4 / §13.

- **Plan effect bound and authority delta** (issue #191): `agentctl plan -o table|json|yaml` prints the desired-graph effect bound (static `uses:` and autonomous agent grants, plus unreachable declared ops) and an **authority delta** vs stored deployment state (`bound(desired)` vs `bound(deployed)` reconstructed from applied `NormalizedSpecJSON`; empty store is an empty baseline — all desired effects are new). An ident reachable by both a static `uses:` and an autonomous grant is tagged **autonomous** (path-max witness, not first static path). Capability delta (concrete `tool.<name>.<operation>` grants) and effect delta (named consequence classes) are separate `RiskItem`s flowing through `FormatPlanSection` / `ExportRisk`. A newly **autonomous** effect is high severity; a newly **static** one is medium; promoting static→autonomous is high. Granting an operation whose effects are already reachable widens capability with an empty effect delta and still marks `authority.autonomous: widened`. JSON/YAML expose structured witness hops plus `effectBound`, `capabilityDelta`, `effectDelta`, and `authority.static` / `authority.autonomous` (`unchanged` | `widened`) so CI can gate on `AUTONOMOUS` `WIDENED`. #204 pin is **not shipped**. DESIGN_DOC §10 / §12.2 J.

- **Effect-bound enforcement against Policy** (issue #190): `Policy.spec.effects.permit` / `permitWithApproval` (second set; not overloaded `permit`). [`effects.Check`](internal/effects) runs on **validate** and **plan** after graph validate — not shared [`config.Resolve`](internal/config), so apply/run/test/inspect/diff/logs/audit/state still load the graph (`run` can reach the engine; `CheckToolCall` remains exit **5**). Unpermitted or unknown reachable effects fail validate/plan with exit **2** and a witness path tagging `AUTONOMOUS` on agent-selection edges. A policy with no permit block permits nothing once any Tool declares `spec.operations`; projects with no declared tool effects skip the check (existing examples still validate). `permit` vs `requiresApproval` / `requiredFor`: stricter wins, including when any reachable op for an ident requires approval and when the same ident is in both permit lists (`permitWithApproval` wins). Widening `effects.permit` — including promoting an ident from `permitWithApproval` to unattended `permit` — is plan risk `effect_permit_widening` (high). #204 pin is **not shipped**. DESIGN_DOC §7.5 / §9.5 / §12.2 J.

- **Transitive effect bounds** (issue #189): [`internal/effects.Compute`](internal/effects) walks an already-resolved desired `ProjectGraph` and returns, for every agent and workflow, the union of declared effects on reachable operations — static `uses:` plus autonomous `agent.spec.tools` grants (concrete `tool.<name>.<operation>` via `[ResolveAgentAdvertisedTools]`, never effect classes). Each effect carries a witness path with `static`/`autonomous` hops; an ident reachable by both is tagged autonomous (path-max, not first-witness). Undeclared reachable ops are explicit unknown (not empty/allow); declared effects on unreachable ops are reported, not omitted. #204 pin is **not shipped** (no MCP `tools/list`; bound is over declared operations). Printed in `agentctl plan` (#191). DESIGN_DOC §12.2 J.

- **Named effects on tool operations** (issue #188): `Tool.spec.operations` maps an operation name to `{ effects: [...] }`. Reserved name `destructive` may derive `spec.safety.sideEffects: true` when that field is omitted. Additive to ToolSafety. DESIGN_DOC §7.3 / §9.3.

- **Bounded agent tool-calling loop** (issue #160): `runAgentStep` resolves `agent.spec.tools` into one `ToolDef` per listed Tool (`ToolChoice: auto`). Entries may be a Tool metadata name or a pinned uses string `tool.<name>.<operation>`. The model may call only that ToolDef name; it maps to a single advertised uses string (native name → `tool.<name>.echo`, mock/mcp name → `tool.<name>.default`, HTTP name is rejected). Pinned HTTP ops must be a real `method.path` (`tool.api.default` is rejected; it would have become `GET /default`). `agentctl validate` / `plan` enforce the same advertised-uses rules. Aliased model names such as `helper.echo` or `helper.command.run` fail before `CheckToolCall` / `Tools.Call`. Inner tool calls inherit `constraints.timeoutSeconds`. The loop runs on `StopReason: tool_use`, appends `tool_result` turns, and stops on `end_turn` or `constraints.maxIterations` (default 8, hard cap 32). `maxIterations` counts Generate turns; `tool_use` on the last turn is not executed. After each Generate and tool turn, `CheckRun` re-evaluates `execution.maxTotalCostUsd` / wall-clock against accumulated loop cost. HITL interrupt is not inside the loop — inner uses must be pre-approved (`--approve`) or `CheckToolCall` fails closed (exit **5**). Hitting the cap records `limit_hit` (`kind: max_iterations`) and fails the step. Agents with no declared tools remain a single completion. Loop model+tool cost accumulates into the step meta.

Each hash covers canonical redacted fields plus the previous event hash. `agentctl audit verify [--run <id>]` re-derives the chain and exits non-zero on breaks; `--limit` controls how many recent runs are scanned without `--run` (default 50, max 500). Pre-migration rows without hashes are reported as **unchained** and do not fail verification. JSON trace output includes `prevHash` / `hash`. See [`docs/AUDIT_CHAIN.md`](docs/AUDIT_CHAIN.md).

Engine, HITL, and policy emissions use typed events (`run_started`, `tool_execution`, `hitl_request_created`, …). Reserved types `memory_read` and `memory_write` are defined but not yet emitted. SQLite migration `006` adds `actor_type` and migrates legacy dot-notation types. `agentctl logs --event <type>` filters by closed vocabulary; unknown values error with the typed list. Inspector timeline and JSON payloads include `timelineIcon`, `timelineGroup`, and OTel `spanName` derived from the same enum.
- **Config resolution hardening** (issue #112): user-local overlays (`~/.config/agentctl/config.yaml`, `.agentic/local.yaml`), strict unknown-key rejection in all YAML layers, and an immutable resolved-config snapshot (`.agentic/resolved-config.json`) with digest checks across `validate`/`plan`/`apply` → `run` (exit **3** on drift). `plan` JSON/YAML includes `resolvedConfigDigest`.

- **Run checkpointing and resume** (issue #105): SQLite `run_checkpoints` table stores per-run execution snapshots after each completed step. `agentctl run --resume <run-id>` rehydrates interpolation context and continues from the next step without replaying earlier steps. ### Changed

- **Breaking — whole-field interpolation preserves JSON types** (issue #193): `${...}` that is the entire field value (`body: ${steps.r.summary}`) no longer stringifies. Objects, arrays, numbers, and booleans keep their types through `with:` and workflow `output.value`. Tokens in surrounding text (`body: "Summary: ${steps.r.summary}"`) still stringify (objects/arrays as JSON text). Workflows without schemas keep the same validation; their runtime `with` / `OutputJSON` for whole-field object/number/bool tokens is now typed rather than a JSON/scalar string. Existing examples still validate and run; `tool.github.pull_request.fetch` now accepts a JSON object for `pr` as well as JSON text so `${input.pr}` (object per input schema) keeps working.

- **IR source positions** (issue #187): `agentctl validate` and `agentctl plan` diagnostics from post-load passes (validator, policy lint) include `file:line:col` from YAML `yaml.Node` coordinates on IR `spec.Pos`. Policy lint for `unknown_required_for_ref` / `unreachable_required_for` / HITL `interruptOn` findings points at the requiredFor item or interruptOn key when stamped; ungated-sensitive-tool stays on the Policy document. Positions are diagnostic metadata only (`json:"-" yaml:"-"` on resource/step fields) and do not change fingerprints, SpecHash, workflow hashes, or resolved-graph digests. Regex scraping of yaml.v3 error text (`yamlLineHint`) is removed; syntax errors with no Node stay Path-only.
- **README comparison table** (issue #174): after Mental model, a table vs OpenAI Agents SDK, LangGraph, Temporal, and Terraform. Positions ACP as the declarative governance/config layer (not durable execution or a code-first agent runtime). Includes a **plan-time effect bound** row: bound compute/enforce/plan output shipped (#189/#190/#191); bound is over the callable operation set, not remote side effects; #204 pin is not enforced (MCP `tools/list` can still expand the world).
- **README lead** (issue #173): first screen is the capability thesis (statically analyzable, capability-oriented execution for nondeterministic programs), a mermaid pipeline (source → validate/plan → SQLite desired state → engine → tools+models → trace/logs/audit), sample `agentctl plan` risk output, and the D1 flagship [`examples/incident-triage`](examples/incident-triage) **above** the feature list. YAML is named as interchange, not the long-term authoring surface. Plan-time effect bound (#189/#191) is printed by `agentctl plan`. Expanded diagram: [`docs/architecture.md`](docs/architecture.md).
- **Roadmap — control flow, capability model, and authoring surface** ([ADR 002](docs/adr/002-language-frontend-and-ir-expressiveness.md), [ADR 003](docs/adr/003-yaml-as-compilation-output.md)). No behavior change; this records two decisions that constrain future work. The `DESIGN_DOC.md` §7.4 "End goal additions" are now ruled on individually: parallel branches, subworkflows, approval steps, and triggers land in the YAML/IR model, while **conditional steps and loops arrive only as a `.agent` language frontend** compiling to this resource model — no `if` / `when` / `foreach` / `expression` field may be added to `WorkflowStep`. YAML is planned to become compilation output and interchange rather than the authoring surface, with the loader remaining fully supported. ADR 002 additionally separates **capability grants** (concrete `tool.<name>.<operation>` references) from **effects** (classes of consequence), names two IR layers (authored resource IR vs. derived execution IR where `Branch`/`Loop` live), and documents the closed-world assumption the effect bound depends on — dynamically discovered MCP operations must be pinned to a deployed manifest or the static bound is unsound. The resource and execution IRs are sibling **projections** of one checked program rather than a pipeline (the resource model cannot represent `Branch`/`Loop`, so the executable form cannot be derived from it), which makes the compiled execution IR a deployment artifact per ADR 001. Authority is separated into **remote discovery** (observation, never authoritative), **desired manifest** (`validate`/`plan`), and **deployed manifest** (`apply`/`run`, pinned per run). Because a pinned digest can only detect change and not reproduce it, deployment artifacts are specified as immutable and content-addressed with an execution-IR format version, so a new `apply` changes what new runs receive without altering what in-flight runs reference. The pinned unit is a whole **deployment snapshot** — an evolution of the existing `.agentic/resolved-config.json` from one current snapshot to retained content-addressed ones — giving the invariant that a run executes against exactly one immutable resolved deployment snapshot for its entire lifetime. `DESIGN_DOC.md` §2 Non-Goals, §7.4, and §20 (new Phases 5–6) updated.
- **Trace event `type` values** (issue #115): persisted and displayed event types are now snake_case (`run_started`, `tool_execution`, …) instead of dot notation (`run.started`, `tool.called`). Migration `006` and read-time normalization upgrade existing SQLite rows; JSON output uses canonical names. Scripts grepping dot-notation types in `agentctl logs` or inspector output should switch to snake_case or use `-o json` with the `type` field. The trace events table adds an `ACTOR TYPE` column (`user` / `agent` / `system`); the run list `ACTOR` column remains the attribution `actor_id` (issue #111).
- **`agentctl logs` table output** (issue #111): the default (non-JSON) run list adds `TENANT`, `THREAD`, and `ACTOR` columns. Scripts that parse fixed column positions should switch to `-o json` or match by header names.
- **Breaking — tool calls without explicit policy are no longer unrestricted.** Previously, `CheckToolCall` with a nil [spec.PolicySpec] allowed all tools. Now fail-closed safety always applies from the project graph (even when the workflow omits `spec.policy` or the Policy resource is missing).
- Tools with **no** `spec.safety` block behave as **untrusted with side effects** after normalization → require `--approve` unless an explicit `approvals.requiredFor` rule matches.

### Migration

1. For **read-only** native or mock tools (echo, fetch, identity), add:
   ```yaml
   spec:
     safety:
       sideEffects: false
   ```
2. For tools where you accept **tool-wide** unattended use but still gate specific operations, set `trusted: true` and list write operations under `Policy.spec.approvals.requiredFor` (exact `uses` strings).
3. Do **not** set `trusted: true` unless you intend every operation on that tool to run without safety-derived approval; per-action gating remains `requiredFor` only (exact match at runtime).
4. For **MCP tools** that rely on server-provided `meta.mcp_flags`, pin explicit `spec.safety` in YAML when you need stable `validate`/`plan`→`run` digests. Resolved-config digests include normalized tool safety; if MCP `tools/list` fails at `plan` time but succeeds at `run` time (or vice versa), effective safety and the digest can change even when project YAML is unchanged (exit **3** drift). `agentctl validate` surfaces non-fatal MCP discovery warnings when listing fails.
