## [Unreleased]

### Added

- **Named effects on tool operations** (issue #188): `Tool.spec.operations` maps an operation name to `{ effects: [...] }`. Effect identifiers are bare dotted names (`[a-z][a-z0-9_]*(\.[a-z][a-z0-9_]*)*`, e.g. `github.read`); `tool.` prefix is rejected. A tool with no declared effects is fail-closed in `[ResolveToolEffects]` (unknown — not an empty/allow set) without changing runtime `CheckToolCall`. Reserved name `destructive` may derive `spec.safety.sideEffects: true` when that field is omitted. Additive to ToolSafety. DESIGN_DOC §7.3 / §9.3.

- **Regression-test example** (issue #176): `examples/regression-test` is an `agentctl test` fixture suite. A trusted mutating mock `publish` is gated by `approvals.requiredFor: [tool.publish.default]`. Empty-`Script` MockClient `tool_use`s that first non-restart tool; inner-loop denial is **exit 5** (`approval_required`), not HITL. `expectError: true` **passes** on the safe policy (`agentctl test` does not `--approve`) and **fails** after dropping the `requiredFor` line. Sample job [`.github/workflows/agentctl-test.yml`](.github/workflows/agentctl-test.yml) (no secrets). Merge gate: `test/integration` copies the example, asserts green then red.
- **Agent loop docs** (issue #175): [`docs/AGENT_LOOP.md`](docs/AGENT_LOOP.md) documents the reason→act→observe loop, advertised uses, `maxIterations` / `ToolChoice: auto`, policy on every inner call, #161 traces, and HITL vs exit **5**. `agent.spec.tools` is an autonomous capability grant (ADR 002 Path 1; Epic A shipped #160/#161). Effect bound (#189/#191) and MCP pin (#204) are **not shipped**. DESIGN_DOC §F/§G updated; README Documentation list links the note.
- **HITL resume example** (issue #172): `examples/hitl-resume` drafts with a tool-less mock agent, then pauses on a workflow `uses:` publish step (`requiredFor` + `hitl.interruptOn`). First `agentctl run` is **interrupted** (exit **0**, checkpoint). `--resume --decision approve` succeeds; logs show `hitl_request_created` then decision/resolution events; `audit verify` passes. This is not agent-loop exit **5**.
- **Environment overlays example** (issue #171): `examples/env-overlays` is one project with **dev** (mock), **staging** (`openai/gpt-4o-mini`), and **prod** (`openai/gpt-4o`, tighter execution, extra `requiredFor` on `tool.notify.default`). `validate -e` each env; `apply -e dev`; `plan -e prod --from-env dev` shows C1 **`model_change`** plus policy field diffs. Cost decrease / added approvals are not relaxation/removal risks. Environment `PolicyOverride` now unions `approvals.requiredFor`. Plan `--from-env` diffs the `-e` overlay against another environment's applied rows (state is per `-e`).
- **Multi-agent handoff example** (issue #170): `examples/multi-agent` runs **triager** then **fixer**. Each agent has its own tools (`lookup` vs trusted mock `patch`) and policy (`triage-readonly` gates `tool.patch.default`; `apply-fix` does not). The first agent's `summary` / `findings` interpolate into the second step. Mock provider, ceilings **$5**, no HITL — the run **succeeds**; logs show both step ids and `llm_completion` events.
- **Audit tamper example** (issue #169): `examples/audit-tamper` runs a successful mock agent step, then plants an edit in `trace_events.data_json` (hash left stale) so `agentctl audit verify --run` fails with exit **1**. Verify passes pre-edit. Helper `scripts/tamper-trace.sh` uses python3 or sqlite3. No HITL; policy ceiling stays above the $0.02 mock Generate.
- **Mid-run budget example** (issue #168): `examples/policy-denial-midrun` runs a two-turn agent tool loop against `execution.maxTotalCostUsd: 0.03`. Empty-`Script` [MockClient] now `tool_use`s the first **non-restart** advertised tool then returns JSON Content (restart-like names still win, Script still wins). The Registry mock attaches **$0.02** per Generate so turn 1 stays under the ceiling and turn 2 trips it (`limit_hit` `kind: max_cost`, exit **5**). Agents with no tools (pr-review-demo) stay single-shot; incident-triage still uses the restart hook.
- **Incident triage example** (issue #167): `examples/incident-triage` is the flagship offline demo — an agent with declared tools (pager / logs / tracker / restart) cannot bounce a service unless `policy.approvals.requiredFor` is pre-approved. Unapproved `agentctl run` exits **5** (`approval_required`); `--approve tool.restart.restart` completes; `audit verify` passes. Empty-`Script` [MockClient] issues a first-turn `tool_use` when `req.Tools` includes a restart-like tool (name is `restart` or contains `restart`) so the gated call actually happens; agents without that tool (pr-review-demo) stay single-shot `Content`.
- **Plan risk output** (issue #166): `agentctl plan -o table|json|yaml` all surface C1 `RiskItem`s. Table groups by severity (`high:` then `medium:` then `low:`). JSON/YAML keep `"risk": []string` and expose structured `"riskItems"` with typed `witness` hops. Rendering goes through `plan.FormatPlanSection` / `plan.ExportRisk` so #191 can add an Effect bound section on the same path.
- **Structured plan risk items** (issue #165): `agentctl plan` classifies diffs as labeled `RiskItem`s (`permission_widening`, `approval_removal`, `budget_relaxation`, `model_change`, `tool_surface_change`, plus existing safety/lint). Each item has severity, reason, target, and a `Witness` hop list (static resource hops in C1; typed for #191 effect-delta paths). Table output prints `[severity] category: reason`. JSON/YAML keep `"risk": []string` (item reasons) and add `"riskItems"`.
- **Mock token usage cost** (issue #164): scripted and client-level [MockClient] `GenerateMeta` token counts flow through the same B1 per-model price table as live OpenAI/Anthropic adapters when `CostUSD` is unset. Explicit non-zero `CostUSD` (for example engine budget tests) is unchanged. Unknown model ids such as `gpt-4` stay at **0**.
- **Run-wide `maxTotalCostUsd` enforcement** (issue #163): accumulated cost is checked before each agent Generate/inner tool call and again after actual cost is applied. Exceeding `execution.maxTotalCostUsd` aborts mid-run with exit **5**, a `limit_hit` event (`kind: max_cost`, `maxTotalCostUsd`, `accumulatedUsd`), `system_error` (`reason: max_cost`), and `run_error`. Cost from earlier workflow steps is carried into later `CheckRun` calls so a later step never starts once the ceiling is already exceeded.
- **Agent-loop tool trace events** (issue #161): inner tool calls in the bounded agent loop emit `tool_selection` (actor `agent`; `tool`, `uses`, and SHA-256 `argumentsDigest` — raw arguments are not stored) then `tool_execution` (`durationMs`, `costUsd`, `success`, and on failure a stable `error: tool_call_failed` — raw `Error()` text is not persisted, so URLs/secrets in HTTP/MCP failures cannot enter the audit chain). Workflow `uses:` steps share the same payload shape. `CheckToolCall` denials still record `system_error` without invoking the tool. Events are hash-linked, so `agentctl logs --run <id>` shows them and `agentctl audit verify --run <id>` covers them.
- **Bounded agent tool-calling loop** (issue #160): `runAgentStep` resolves `agent.spec.tools` into one `ToolDef` per listed Tool (`ToolChoice: auto`). Entries may be a Tool metadata name or a pinned uses string `tool.<name>.<operation>`. The model may call only that ToolDef name; it maps to a single advertised uses string (native name → `tool.<name>.echo`, mock/mcp name → `tool.<name>.default`, HTTP name is rejected). Pinned HTTP ops must be a real `method.path` (`tool.api.default` is rejected; it would have become `GET /default`). `agentctl validate` / `plan` enforce the same advertised-uses rules. Aliased model names such as `helper.echo` or `helper.command.run` fail before `CheckToolCall` / `Tools.Call`. Inner tool calls inherit `constraints.timeoutSeconds`. The loop runs on `StopReason: tool_use`, appends `tool_result` turns, and stops on `end_turn` or `constraints.maxIterations` (default 8, hard cap 32). `maxIterations` counts Generate turns; `tool_use` on the last turn is not executed. After each Generate and tool turn, `CheckRun` re-evaluates `execution.maxTotalCostUsd` / wall-clock against accumulated loop cost. HITL interrupt is not inside the loop — inner uses must be pre-approved (`--approve`) or `CheckToolCall` fails closed (exit **5**). Hitting the cap records `limit_hit` (`kind: max_iterations`) and fails the step. Agents with no declared tools remain a single completion. Loop model+tool cost accumulates into the step meta.
- **Provider token cost estimates** (issue #162): `GenerateMeta.CostUSD` is computed from `PromptTokens` / `CompletionTokens` × a data-driven per-model price table for OpenAI and Anthropic (`internal/models/cost.go`; standard input/output rates only). Dated snapshot ids match `key-` plus a year or YYYYMMDD (for example `claude-sonnet-4-20250514`). Newer version ids that only share a shorter prefix (`claude-sonnet-4-5-…`) stay at **0** until added to the table.
- **Anthropic Messages API tool calling** (issue #158): the Anthropic adapter maps `GenerateRequest.Tools` / `ToolChoice` to Messages `tools` / `tool_choice` (`required` → `any`), parses `tool_use` content blocks into `GenerateResponse.ToolCalls` with `StopReason` (`tool_use` / `end_turn` / `max_tokens`; unknown reasons such as `refusal` are passed through), and sends prior `ChatMessage.ToolCalls` plus `ToolResults` as assistant `tool_use` then user `tool_result` blocks. Consecutive `ToolResults` turns are merged so roles still alternate. Empty tool output still sends `content: ""`. Plain `end_turn` with no text still errors (`anthropic: no text content in response`); `tool_use` may omit text. Token usage comes from `usage.input_tokens` / `output_tokens`.
- **OpenAI Chat Completions tool calling** (issue #157): `OpenAIClient` sends `GenerateRequest.Tools` / `ToolChoice`, parses `tool_calls` into `GenerateResponse.ToolCalls` with `StopReason` (`tool_use` / `end_turn` / `max_tokens`), and accepts prior `ChatMessage.ToolCalls` plus `ToolResults` as assistant + `role: "tool"` messages. Token usage and cost still come from the API `usage` block.
- **Mock model tool-call scripting** (issue #159): `MockClient` accepts a sequence of scripted `Generate` turns (for example turn 1 → `tool_use`, turn 2 → final text/JSON), records each request so tests can assert on `Tools`, and supports per-call token counts on `GenerateMeta`. Single-shot `Content`/`Meta` behavior is unchanged aside from setting `StopReason: end_turn`.
- **Tamper-evident trace audit chain** (issue #116): per-run hash-linked `trace_events` (`prev_hash`, `hash`; migration `007`). Each hash covers canonical redacted fields plus the previous event hash. `agentctl audit verify [--run <id>]` re-derives the chain and exits non-zero on breaks; `--limit` controls how many recent runs are scanned without `--run` (default 50, max 500). Pre-migration rows without hashes are reported as **unchained** and do not fail verification. JSON trace output includes `prevHash` / `hash`. See [`docs/AUDIT_CHAIN.md`](docs/AUDIT_CHAIN.md).
- **Closed trace event taxonomy** (issue #115): versioned `EventType` and `ActorType` enums in `internal/trace` (`TaxonomyVersion` 1). Engine, HITL, and policy emissions use typed events (`run_started`, `tool_execution`, `hitl_request_created`, …). Reserved types `memory_read` and `memory_write` are defined but not yet emitted. SQLite migration `006` adds `actor_type` and migrates legacy dot-notation types. `agentctl logs --event <type>` filters by closed vocabulary; unknown values error with the typed list. Inspector timeline and JSON payloads include `timelineIcon`, `timelineGroup`, and OTel `spanName` derived from the same enum.
- **Config resolution hardening** (issue #112): user-local overlays (`~/.config/agentctl/config.yaml`, `.agentic/local.yaml`), strict unknown-key rejection in all YAML layers, and an immutable resolved-config snapshot (`.agentic/resolved-config.json`) with digest checks across `validate`/`plan`/`apply` → `run` (exit **3** on drift). `plan` JSON/YAML includes `resolvedConfigDigest`.
- **Run attribution** (issue #111): `tenant_id`, `thread_id`, `actor_id`, `parent_run_id`, `request_id`, `idempotency_key`, and `source` on `runs`; trace events carry matching tenant/thread/actor for filterable logs and inspector queries. `agentctl run` accepts `--tenant-id`, `--thread-id`, `--actor-id` (local defaults `tenant-1` / `thread-1` / `user-1`); `agentctl logs` and `GET /api/runs` filter by the same dimensions. `--resume` reuses persisted `run_id` and `thread_id`. OTel spans emit `gen_ai.tenant.id`, `gen_ai.thread.id`, `gen_ai.actor.id`, and `gen_ai.request.id`. See [`docs/ATTRIBUTION.md`](docs/ATTRIBUTION.md).
- **Trace payload redaction** (issue #110): trace events are sanitized, key-redacted, and size-capped before SQLite storage. Defaults mask common secret key names; override via `Project.spec.traces.redactKeys`, `maxPayloadBytes`, and `spec.traces.redaction` (`maxDepth`, `maxBytes` for binary previews, `maxStringChars`). HITL edit `argsDiff` is redacted before persistence. Local runs use [trace.NewRecorderForGraph] from project spec.
- **Optional OpenTelemetry trace export** (issue #108): `Project.spec.telemetry` (`enabled`, `serviceName`, `endpoint` with `env:` tokens, `consoleExport`) emits WayFind-aligned `gen_ai.*` spans (`agent.run`, `model.chat`, `tool.exec`, `approval`) alongside SQLite traces. Disabled by default; init failures log a warning and never fail runs. See [`docs/OTEL.md`](docs/OTEL.md) for a Jaeger quick start.
- **`agentctl inspect --web`** — read-only local inspector (default `http://127.0.0.1:8787`) over SQLite state: runs, trace timeline, run steps, applied deployment resources, and checkpoints ([#109](https://github.com/LAA-Software-Engineering/agentic-control-plane/issues/109)).
- **Run checkpointing and resume** (issue #105): SQLite `run_checkpoints` table stores per-run execution snapshots after each completed step. `agentctl run --resume <run-id>` rehydrates interpolation context and continues from the next step without replaying earlier steps. Interrupted runs exit cleanly (status `interrupted`, exit code 0) and cascade with trace retention pruning. Checkpoints are written before step rows are marked succeeded to avoid replay on crash; runs pin `workflow_spec_hash` and `environment_name` for safe resume.
- **Built-in policy presets** (issue #104): `strict`, `permissive`, and `shell_safe`. Select via `Project.spec.defaults.policy`, by referencing a preset name on agents/workflows, or with `Policy.spec.preset` (local rules layer on top). Presets expand during [NormalizeProjectGraph]; `strict`/`permissive` materialize approval flags, while `shell_safe` sets `ResolvedPreset` and relies on runtime token classification plus tool safety metadata for plan risk.
- **`shell_safe` token classification** for native `command.run` / `run` / `exec` / `shell` operations: read-only first tokens (`ls`, `cat`, …) run unattended when the command contains no shell metacharacters (`;|&$`, newlines, `` ` ``, `$(…)`); risky tokens, unknown tokens, and side-effecting non-shell tools require `--approve`. **Heuristic only — not a sandbox.**
- **`spec.safety` on Tool resources** (issue #103): optional `trusted`, `sideEffects`, and `requiresApproval` fields. [NormalizeProjectGraph] materializes fail-closed defaults on load.
- **Policy safety fallback**: when no `approvals.requiredFor` entry matches the exact `uses` string, [policy.Derive] consults resolved safety metadata. Unattended mutating tools require `--approve` (exit code **5**, `approval_required`).
- **Plan risk hints** for tools that will require approval at run, including decision source (`explicit_policy_rule`, `safety_metadata`, `fail_closed_default`).
- **MCP tool safety discovery** (issue #125): during config resolution, MCP `tools/list` descriptors supply `meta.mcp_flags` (`trusted`, `side_effects`, `requires_approval`) merged into `spec.safety` via [spec.SafetyFromMCPMeta] and [spec.MergeToolSafety]. Author-set YAML fields override MCP per field; discovery failures fall back to fail-closed defaults and emit validate-time warnings on [config.ResolvedConfig.MCPDiscoveryWarnings].

### Changed

- **IR source positions** (issue #187): `agentctl validate` and `agentctl plan` diagnostics from post-load passes (validator, policy lint) include `file:line:col` from YAML `yaml.Node` coordinates on IR `spec.Pos`. Policy lint for `unknown_required_for_ref` / `unreachable_required_for` / HITL `interruptOn` findings points at the requiredFor item or interruptOn key when stamped; ungated-sensitive-tool stays on the Policy document. Positions are diagnostic metadata only (`json:"-" yaml:"-"` on resource/step fields) and do not change fingerprints, SpecHash, workflow hashes, or resolved-graph digests. Regex scraping of yaml.v3 error text (`yamlLineHint`) is removed; syntax errors with no Node stay Path-only.
- **README comparison table** (issue #174): after Mental model, a table vs OpenAI Agents SDK, LangGraph, Temporal, and Terraform. Positions ACP as the declarative governance/config layer (not durable execution or a code-first agent runtime). Includes a **plan-time effect bound** row: full bound is direction (#189/#190/#191, not shipped); today `agentctl plan` diffs permissions, approvals, models, budgets, and C1 risk items; bound is over the callable operation set, not remote side effects; #204 pin is not enforced (MCP `tools/list` can still expand the world).
- **README lead** (issue #173): first screen is the capability thesis (statically analyzable, capability-oriented execution for nondeterministic programs), a mermaid pipeline (source → validate/plan → SQLite desired state → engine → tools+models → trace/logs/audit), sample `agentctl plan` risk output, and the D1 flagship [`examples/incident-triage`](examples/incident-triage) **above** the feature list. YAML is named as interchange, not the long-term authoring surface. Direction toward a plan-time effect bound (#189/#191) is stated without claiming that product is shipped. Expanded diagram: [`docs/architecture.md`](docs/architecture.md).
- **Roadmap — control flow, capability model, and authoring surface** ([ADR 002](docs/adr/002-language-frontend-and-ir-expressiveness.md), [ADR 003](docs/adr/003-yaml-as-compilation-output.md)). No behavior change; this records two decisions that constrain future work. The `DESIGN_DOC.md` §7.4 "End goal additions" are now ruled on individually: parallel branches, subworkflows, approval steps, and triggers land in the YAML/IR model, while **conditional steps and loops arrive only as a `.agent` language frontend** compiling to this resource model — no `if` / `when` / `foreach` / `expression` field may be added to `WorkflowStep`. YAML is planned to become compilation output and interchange rather than the authoring surface, with the loader remaining fully supported. ADR 002 additionally separates **capability grants** (concrete `tool.<name>.<operation>` references) from **effects** (classes of consequence), names two IR layers (authored resource IR vs. derived execution IR where `Branch`/`Loop` live), and documents the closed-world assumption the effect bound depends on — dynamically discovered MCP operations must be pinned to a deployed manifest or the static bound is unsound. The resource and execution IRs are sibling **projections** of one checked program rather than a pipeline (the resource model cannot represent `Branch`/`Loop`, so the executable form cannot be derived from it), which makes the compiled execution IR a deployment artifact per ADR 001. Authority is separated into **remote discovery** (observation, never authoritative), **desired manifest** (`validate`/`plan`), and **deployed manifest** (`apply`/`run`, pinned per run). Because a pinned digest can only detect change and not reproduce it, deployment artifacts are specified as immutable and content-addressed with an execution-IR format version, so a new `apply` changes what new runs receive without altering what in-flight runs reference. The pinned unit is a whole **deployment snapshot** — an evolution of the existing `.agentic/resolved-config.json` from one current snapshot to retained content-addressed ones — giving the invariant that a run executes against exactly one immutable resolved deployment snapshot for its entire lifetime. `DESIGN_DOC.md` §2 Non-Goals, §7.4, and §20 (new Phases 5–6) updated.
- **Trace event `type` values** (issue #115): persisted and displayed event types are now snake_case (`run_started`, `tool_execution`, …) instead of dot notation (`run.started`, `tool.called`). Migration `006` and read-time normalization upgrade existing SQLite rows; JSON output uses canonical names. Scripts grepping dot-notation types in `agentctl logs` or inspector output should switch to snake_case or use `-o json` with the `type` field. The trace events table adds an `ACTOR TYPE` column (`user` / `agent` / `system`); the run list `ACTOR` column remains the attribution `actor_id` (issue #111).
- **`agentctl logs` table output** (issue #111): the default (non-JSON) run list adds `TENANT`, `THREAD`, and `ACTOR` columns. Scripts that parse fixed column positions should switch to `-o json` or match by header names.
- **Breaking — tool calls without explicit policy are no longer unrestricted.** Previously, `CheckToolCall` with a nil [spec.PolicySpec] allowed all tools. Now fail-closed safety always applies from the project graph (even when the workflow omits `spec.policy` or the Policy resource is missing).
- Tools with **no** `spec.safety` block behave as **untrusted with side effects** after normalization → require `--approve` unless an explicit `approvals.requiredFor` rule matches.

### Migration

1. For **read-only** native or mock tools (echo, fetch, identity), add:
   ```yaml
   spec:
     safety:
       sideEffects: false
   ```
2. For tools where you accept **tool-wide** unattended use but still gate specific operations, set `trusted: true` and list write operations under `Policy.spec.approvals.requiredFor` (exact `uses` strings).
3. Do **not** set `trusted: true` unless you intend every operation on that tool to run without safety-derived approval; per-action gating remains `requiredFor` only (exact match at runtime).
4. For **MCP tools** that rely on server-provided `meta.mcp_flags`, pin explicit `spec.safety` in YAML when you need stable `validate`/`plan`→`run` digests. Resolved-config digests include normalized tool safety; if MCP `tools/list` fails at `plan` time but succeeds at `run` time (or vice versa), effective safety and the digest can change even when project YAML is unchanged (exit **3** drift). `agentctl validate` surfaces non-fatal MCP discovery warnings when listing fails.
